9. Algo todavía más interesante: podemos implementar el lector

La respuesta de los meters tiene esta estructura prácticamente confirmada:

40/50/60/70 ...
   │
   ├── 0C       longitud
   ├── 0A
   ├── 31 82
   ├── grupo
   ├── meter
   ├── 00
   ├── VALUE[4]
   └── CRC[2]

Por ejemplo:

40 0C 0A 31 82 02 04 05 00 02 21 1E FF 00 CB F3
                  │  │  │     └─────────┘
                  │  │  │          VALUE
                  │  │  └── 05
                  │  └───── 04
                  └──────── 02

Y el valor es simplemente:

uint32_t value =
    ((uint32_t)rx[pos]   << 24) |
    ((uint32_t)rx[pos+1] << 16) |
    ((uint32_t)rx[pos+2] << 8)  |
    ((uint32_t)rx[pos+3]);

Es decir, los meters que hemos identificado están en Big Endian de 32 bits.

1. Algoritmo CRC identificado

El protocolo está utilizando:

CRC-16/XMODEM

Parámetros:

Polynomial : 0x1021
Initial    : 0x0000
XOR Out    : 0x0000
Reflect In : NO
Reflect Out: NO

Es decir:

CRC-16
poly = 0x1021
init = 0x0000
xorout = 0x0000

Y el CRC se transmite MSB primero:

CRC = 0xBFBA

TX:
... BF BA

Por ejemplo, una de las consultas es:

68 06 05 30 02 81 01 01 BF BA

Los primeros 8 bytes son los datos:

68 06 05 30 02 81 01 01

y el CRC calculado es:

BF BA

Esto coincide con la captura.

Código C para el ESP32

Puedes implementar exactamente:

uint16_t gamma_crc16(const uint8_t *data, size_t len)
{
    uint16_t crc = 0x0000;

    for (size_t i = 0; i < len; i++)
    {
        crc ^= ((uint16_t)data[i] << 8);

        for (uint8_t j = 0; j < 8; j++)
        {
            if (crc & 0x8000)
                crc = (crc << 1) ^ 0x1021;
            else
                crc <<= 1;
        }
    }

    return crc;
}

Y para agregarlo:

uint16_t crc = gamma_crc16(tx, 8);

tx[8] = (crc >> 8) & 0xFF;
tx[9] = crc & 0xFF;

4. Ahora podemos conocer el CRC de cada consulta

Aquí hay una aclaración importante sobre tu pregunta.

Preguntas:

"Para consultar un contador específico del lado del TX la consulta siempre es la misma entonces el CRC de cada comando de consulta es el mismo?"

Sí, pero con una condición.

El CRC depende de todos los bytes anteriores al CRC.

Por ejemplo:

48 06 05 30 02 02 04 05 CRC

siempre que esos 8 bytes sean exactamente iguales, el CRC siempre será exactamente el mismo.

Pero hay un detalle:

El primer byte cambia.

Por ejemplo, para una misma familia de consultas tenemos:

48 ...
58 ...
68 ...
78 ...

Por lo tanto:

48 06 05 30 02 02 04 05

tendrá un CRC.

Pero:

58 06 05 30 02 02 04 05

tendrá otro CRC.

Aunque el Tipo/Subgrupo/Meter sea idéntico.
